# 主播表情与口型：实现和验收

本次优化保持固定 9∶16 播出窗口，不增加 OBS、模型下载或运行时依赖。重载大肥鱼插件并重新打开播出窗口后生效。

## 当前实现

- 流式 PCM 与整段语音记录实际安排的播放时间。优先使用 AudioContext 输出设备时间戳，缺失时按设备延迟回退；每次读取对应播放位置附近约 10ms 的音频。源节点结束后等待设备尾音，取消或紧急停止立即释放。
- 窗口上传目标间隔 16ms，每次只允许一个请求；后端用 SSE 立即推送最新状态，替代原来的两次 66ms 轮询。160ms 以上的语音样本不再驱动张嘴；推送断开或工作台心跳过期转安全画面。实际频率受设备负载和浏览器后台限速影响。
- 嘴型采用与帧率无关的指数平滑。句中短暂停顿保留上一次音量驱动的约 15%，最大开口 0.09，180ms 后回收；长静音、空闲和倾听收口。不会为追求“呼吸感”持续张嘴。
- 倾听时轻微点头，长倾听中间隔约 5.2–8.7 秒再次轻微回应；随机眨眼包含快闭、短暂停留、慢睁，立绘以上眼睑下落为主。装载时先保持睁眼，避免初始化误闭眼。缓慢变动头部目标位置；呼吸组合不同频率以减少明显重复。操作系统“减少动态”设置会关闭附加动作，保留语音嘴型。
- 头部不再跟随每次嘴部开合抖动，而是通过间隔受限的语音能量重音产生轻微点头；倾听、说话和静音之间保留姿态连续性。情绪变化参考较慢的语句能量包络，避免眉眼逐音节跳动。
- Live2D 使用模型实际存在的口型、眉眼、眼球与头部参数，缺少参数时跳过。夏夏、沈露白、谷雨、贝拉优先使用完整 2.5D 面部网格：原图作纹理，统一计算皮肤、下颌、眉眼和口唇形变；眼球与口腔按动态边界遮挡，补建上下牙齿和舌头。完整模型生效时关闭旧嘴部和眼部局部变形。原有头部分层、饰品和透明度遮罩继续使用。
- 模型绑定原图 SHA256；更换原图后须重新生成，不允许错配脸部定位。未安装完整模型的其他角色仍使用原有降级路径。详见 [四角色面部模型](face-rig-models.md)。
- **口型时间线（0.17.0）**：`src/avatar/lip-timeline.ts` 把口型从「按音量开合」升级为「按采样位置的口型序列」。每段记录 `turnId` / `profileId` / 采样率 / 起止采样位置 / 顺序号 / 来源（`aligned` 对齐 · `estimated` 估计），逐帧给出 6 维 viseme 权重（开口、闭唇、圆唇、横展、露齿、微笑）。工作台按**实际播放位置**求值并做短线性插值，窗口外返回 null（不外推、不无限延长边缘帧）；`b/p/m` 的闭唇权重直接压制开口，句中停顿的呼吸余量不能让嘴保持张开。同话轮只接受更大顺序号，跨话轮与换角色的样本拒收；打断递增播出版本，迟到样本一律丢弃。渲染端（`applyVisemePose`）把圆唇映射为负 `mouthForm`、横展映射为正，与 Live2D 参数方向一致。对齐数据尚未接入前，`visemeFromSample` 用现有过零率代理只给出**形状**维度（圆唇/横展），开合幅度仍交回原平滑器——因此这条链路虽然已经接通，但**还没带来音素级精度**；viseme 全零时完整回退旧路径（有逐位等价测试）。
- **对话动作（0.17.0 模块 / 0.17.1 接线）**：`src/avatar/dialogue-motion.ts`（参考实现 + 单测）与 `client/client.js` 内联等价状态机 `createDialogueMotion`（client 为无构建单文件，不能 import TS 模块）把弹幕到达、输入开始/停顿、等待回复、首音、尾音、打断、紧急停止翻译成姿态目标（视线、头肩、点头、眉眼、倾斜）。**接线范围**：直播画面页（BroadcastStage，弹幕轮询 + speech.phase 边沿驱动）与独立播出窗口（BroadcastOutput，SSE 帧边沿 + 互动轮次驱动）；两处渲染路径（Live2D / 2.5D 原型）经 `blendDialogueTargets` 叠加。眨眼与呼吸仍由 `createAvatarMotion` 负责。连发弹幕按合并窗口（700ms）合并、重触发限频（1.8s），刷屏不会让角色变成不停点头的机器；说话期间动作权重压到 45%，不与口型抢注意力；`interrupt()` 与安全态回到中性并递增版本。**未接线**：工作台内嵌小预览（EciyuanPreview）仍走原路径。改动后需重载插件并重新打开直播画面/播出窗口才生效。
- **播出播放版本（0.17.0）**：`BroadcastWindow` 在切角色、进出安全画面时递增 `playbackVersion`；工作台可声明自己所属版本，声明了旧版本的上行帧被直接拒收——本机已调度播放与窗口内迟到帧都靠这一层挡住。`POST broadcast-window/interrupt` 供工作台主动打断；`live/stop` 与 `live/emergency-stop` 走同一条作废路径。
- 情绪只从进入播放的回复提取有限风格提示，强度有上限，严肃提示优先于积极提示。Live2D 和完整面部网格联动眉眼、嘴角；它不是语音情感识别模型。
- 保留既有回复检查、AI 标识和紧急停止。面向观众的互动卡不再原样展示未经审核的用户名和弹幕，改为互动状态；操作工作台仍可查看原文。表情规则不替代内容审核，既有规则也不是完整的语义合规审核。

## 验证方法与证据范围

自动化覆盖 PCM 定位、时钟回退、30/60/120 FPS 平滑、短停顿/长静音、安全态、眼部配置降级、音频尾音等待、鉴权推送和过期语音清除；0.17.0 追加口型时间线（插值/边界/闭唇/拒收/版本/降级留痕/首音记账）、对话动作（阶段推进/连发合并/限频/打断）、播出版本（切角色/停播/紧急停止/旧帧拒收）与客户端 viseme 映射。纯数学测试的 80ms 跟随结果仅证明平滑器响应，不是实际音画误差。

可复现的本机画面检查：

```sh
pnpm build
node scripts/verify-broadcast-motion.mjs
```

使用已安装的 Chrome（可用 `DAFEIYU_TEST_CHROME` 指定路径）和临时插件数据。只发送合成动作帧，不合成声音、不连接直播间、不修改生产会话；报告和四个角色截图输出到临时目录。测试保留真实上传接口、SSE、素材接口和共享 React 渲染器，以替身进程代替原生窗口启动。

2026-11-18 本机一次检查收集 188 个说话渲染样本：样本上传至渲染回调年龄 P95 **19ms**，渲染回调间隔 P95 **17.7ms**，过期样本计数 0，页面错误 0。紧急停止和断连均切入暂停画面。另以固定动作时刻检查闭眼/睁眼帧。该结果不含声音设备、窗口实际呈现、直播伴侣和平台编码，不是端到端音画同步验收，也不是持续负载帧率保证。

窗口调试环境可调用 `window.__dafeiyuMotionMetrics()` 获取最近 600 个有效语音渲染样本的 P95、渲染间隔、过期计数和样本数。未采样返回 null；过期样本单独计数，不计入有效样本分位数。指标不包含字幕或观众正文。

## 未达成的指标与下一步验收

| 项目 | 本次状态 | 实际验收方式 |
| --- | --- | --- |
| 端到端口型误差 ≤80ms | 目标，尚未证明 | 同时录下直播伴侣最终视频和实际输出音频，测量多段语句的有符号偏移、P95、最大偏移；至少覆盖高负载、切页、断连和长句 |
| 输入结束到首个可听回复 1–2s | 尚未验收，受识别/模型/TTS影响 | 分别记录输入结束、审核完成、首音频数据、实际设备首音，统计冷启动和热启动 |
| 音素级唇形匹配 | 时间线与渲染已就绪，**对齐数据尚未接入** | 0.17.0 已提供 viseme 六维通道、按播放位置求值与闭唇覆盖，但当前 Qwen 参考音色进程只输出 PCM、不返回发音时间戳：时间线目前按 `estimated` 装载并计入降级统计（`LipTimelinePlayer.stats().degraded`）。接入 TTS 音素时间戳或强制对齐后改标 `aligned`，届时该行的口径才成立 |
| 口型时间线求值正确性 | 已单测（纯函数） | `src/avatar/lip-timeline.test.ts`：插值、窗口边界不外推、闭唇压制、顺序号/跨话轮/换角色拒收、装载窗口校验、打断增版本、降级留痕、首音三段记账（含未测到如实为 null）。**这些是数学与状态机测试，不是实际音画误差** |
| LMD、Sync-C/Sync-D、95% 匹配率 | 未评测 | 固定数据集、帧率、裁脸/关键点坐标及归一化方法、模型版本；以最终录制文件评估 |
| 1 像素表情偏差 | 未评测；中性纹理一致性检查不等于表情准确度 | 需有参考动作与对应标注；像素误差必须指定画面尺寸和对齐方式 |
| 倾听主观自然度 | 已接线（0.17.1），尚未用户验收 | 直播画面页与独立播出窗口由弹幕/思考/首音/尾音事件驱动姿态（合并窗口与重触发限频有单测覆盖，`src/avatar/dialogue-motion.test.ts` 与 client vm 用例）；「点得是否自然」仍需真人盲评，且需重载插件后在实际预览中确认 |
| 播出打断与迟到帧 | 已单测 | `src/live/broadcast-window.test.ts` 新增：切角色递增版本、旧版本上行帧拒收、`interrupt()` 清帧并递增、非 owner 不能打断。实测时仍需在真实窗口里验证打断后画面与声音同时收口 |

四个角色现已具备连续面部网格、眼球遮挡和分层口腔。牙齿、舌头是依据现有正面素材补建的近似几何，不是对原角色隐藏口腔的真实重建；面部网格也不是可任意转头的完整 3D 头模。当前能减少局部贴片接缝，但不能保证所有表情都没有失真。音素级匹配和写实情绪仍需音素/情感时序数据及真实录制评估，不能用音量驱动代替验收。

## 标准与研究口径

- [广电总局 GY/T 411-2024 官方发布页](https://www.nrta.gov.cn/art/2024/11/28/art_3704_69715.html)：核对正文 7.3.1，要求口唇自然且与发音同步；没有找到“口型误差 ≤80ms”的量化条款。本项目把 80ms 当作内部目标，不标记为通过行业标准认证。
- [ITU-R BT.1359-1](https://www.itu.int/rec/R-REC-BT.1359-1-199811-I/en)：可察觉阈值与可接受阈值属于不同口径，音频领先/滞后也不对称；不能混写成统一商业合格线。
- [Web Audio API](https://www.w3.org/TR/webaudio-1.1/)：本实现根据输出设备时间戳关联音频时钟和页面时钟；仍需用实际录制验证设备与采集路径偏移。
- [UniLS 论文](https://arxiv.org/abs/2512.09327)：倾听改进和生成速度是其研究设置的结果。本项目没有集成该模型，也不继承其指标。
