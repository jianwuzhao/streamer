# 四角色骨骼主播重构方案

采用 **独立三维角色、独立场景和固定机位**。待机、倾听和说话共享同一角色实例，椅子、桌面和远景固定在场景坐标里。身体动作只驱动人物的骨骼和按规则绑定的手持物，面部单独驱动嘴型、眉眼和视线。

## 已接入的独立样板 · 夏夏重构版

工作台「预览角色」可分别选择夏夏和夏夏 · 重构版。之前保存的澜序选择会迁移到重构版。重构版在待机、倾听和说话时使用原图的坐姿、衣服和手部，面部单独驱动口型和眨眼。独立播出以 1080×1920 渲染，验证覆盖说话时身体和背景固定、手部与原图匹配，以及口型变化。

开发目录执行 `pnpm avatar:build-3d` 可在本地重新生成模型几何。播出使用 GLB 的面部网格与本地安装的夏夏立绘，校验源图摘要后启用模型。角色加载失败时回退到本地原立绘。离线手部资产仍可用于建模，其拓扑、绑定和源版本记录在 `scripts/assets/xiaxia-hand.json` 中。

## 当前素材与问题

- 夏夏的原图把人物、椅子和房间合成在一张图上。实查右侧椅背区域，原图坐标 `(592, 470)`、`(612, 492)`、`(570, 441)` 在头部遮罩里的透明度均为 255，在身体遮罩里分别为 255、250、255。肩臂变形读取整张原图，再以这份遮罩裁剪，所以椅背会随人体重采样。校正这些点可以减少一次误判，角色与场景的边界仍由照片遮罩决定。
- 参考视频提供了可观察的动作和正面外貌。当前四角色素材目录包含原图、短视频、遮罩、唇部跟踪和面部网格，尚未找到可用的骨骼角色源文件。手指背面、耳麦与头发遮挡处、手离开原位置后露出的场景需要独立建模或修复。

## 技术选型

| 路线 | 本项目的用途 |
| --- | --- |
| **Blender 制作 + glTF 2.0 GLB + Three.js** | 主路线。原貌由独立模型的几何、材质和灯光还原，头、肩、手指均可单独控制，场景可独立校验。Blender 仅用于制作，Three.js 运行时随插件打包。 |
| VRM 1.0 | 若取得的原始资产本身采用 VRM，可用 Three.js 与 three-vrm 加载。首版用 GLB 交付角色及自制动作，减少格式转换。 |
| RuiC-2D 与整段视频生成 | RuiC-2D 可继续服务于轻量角色。LiveTalking 的音频分块、时钟和打断逻辑继续作为参考。预制视频可用于对比动作质量，实时播出使用同一骨骼角色实例。 |

glTF 支持骨骼蒙皮、动画和面部形状目标。Three.js 提供 GLTFLoader 和动画混合，WebGLRenderer 需要 WebGL 2。VRM 1.0 提供标准人形骨骼和表情约定。实际 WebKit 环境的显存、帧率和直播伴侣采集仍需用带贴图的角色实测。 [Blender glTF 插件](https://github.com/KhronosGroup/glTF-Blender-IO) · [glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) · [Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) · [动画混合](https://threejs.org/docs/pages/AnimationMixer.html) · [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html) · [VRM 1.0 规范](https://github.com/vrm-c/vrm-specification/blob/master/specification/VRMC_vrm-1.0/README.md)

本机已在独立的 WKWebView 探针里创建 WebGL 2 上下文并读取渲染像素。这项检查验证了所需的图形接口，角色蒙皮、贴图负载和窗口采集将在样板阶段测量。

## 夏夏样板

1. **补齐三类资产。** 优先取得或制作与夏夏外貌匹配的角色源工程，包括脸型、发型、耳麦、服装、牙齿与手掌。制作独立的无人物房间底图、椅子和桌面。固定机位下，椅子和桌面可用独立静态图层配合深度遮挡，人物移动后露出的区域在制作阶段补全。
2. **制作四段动作验证完整链路。** 待机呼吸、倾听点头和轻前倾、说话时手掌抬到画面内、回复结束让手落回桌面。手腕和肘关节使用目标约束保持接触，手指形状从模型的骨骼或预设手势取得。耳麦随头骨，椅子留在场景坐标。
3. **运行时分工。** 动作状态机按现有互动事件切换姿态。身体动作轨道控制脊柱、肩臂和手，脸部轨道读取语音播放时钟上的嘴型和表情。音量重音可在动作允许时触发有限的小动作。音素时间戳可用后再接入口型时间线，现有音频估计继续提供降级驱动。
4. **接入播出。** 给工作台预览和独立窗口接入共享三维渲染适配层，复用现有本机资源权限、单路音频、字幕滚动和打断版本。按角色配置启用已验收的资产。模型加载失败时显示独立静态画面或安全画面。首次接入以固定 9∶16 的 macOS 独立播出窗口为验收环境。

样板角色包包含嵌入贴图的 `character.glb`、独立背景与必要的前景遮挡图层，以及记录镜头、姿态片段、手部锚点、角色资源版本和表情映射的清单。首版脸部需单独绑定闭唇、开口、圆唇、横展、左右眨眼与眉眼表情。

## 验收后再扩展

| 检查 | 样板通过条件 |
| --- | --- |
| 外貌 | 原图和新角色采用相同正面构图对照，复核五官、发色、发型、耳麦和服装，重点确认未换成通用风格。 |
| 背景与遮挡 | 手抬起、前倾、复位时椅子和桌面坐标不变。离屏测试对比背景图层像素，最终合成帧排除人物遮挡及轮廓边缘后，静态背景区域像素保持一致。 |
| 肢体 | 连续完成「倾听 → 开口抬手 → 回桌」，手指完整，手腕和桌面的接触位置连续，肩、肘和布料无明显穿插。 |
| 播出 | 在目标 Mac 原生窗口实测 WebGL 2、连续播放和切换角色。录制直播伴侣最终画面与单路音频，测量口型偏差和实际帧率，并验证字幕、安全画面与断连。 |

通过后为沈露白、谷雨和贝拉制作各自模型、道具锚点和动作。沈露白优先验证持杯，谷雨验证手与打蛋器和碗的接触，贝拉验证屈膝时的重心和手臂平衡。四人共用播出接口与动作状态，外貌和动作库按角色制作。
